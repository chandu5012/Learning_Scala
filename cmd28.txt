Review the complete existing Python Azure Function implementation before making any changes.

OBJECTIVE

Currently the SOX processing flow generates a User Delegation SAS URL for the processed/source file and writes that SAS URL directly into the Confluence page.

Problem:

The SAS URL expires after a configured period. After expiration, users can no longer download the file from the Confluence page.

Required design:

Do NOT store a SAS URL directly in Confluence.

Instead, store a permanent Azure Function download URL.

When a user clicks the link:

Confluence
    ↓
Permanent download Function URL
    ↓
download Function receives file_id
    ↓
Resolve file_id to the correct Azure Blob
    ↓
Validate file/user/request
    ↓
Generate a NEW short-lived User Delegation SAS
    ↓
Return HTTP 302 redirect
    ↓
Browser follows fresh SAS URL
    ↓
File downloads from Azure Blob Storage

This allows the Confluence link to remain permanent while each actual Storage SAS token remains short-lived.

============================================================

The queue message/event already identifies the specific file that triggered processing.

============================================================
3. INTRODUCE FILE_ID
============================================================

For every file processed by the queue-trigger Function, create a stable file_id.

Do NOT use a temporary SAS token as the file identifier.

Preferred implementation:

Use a deterministic opaque ID derived from the immutable blob reference.

For example:

file_id = SHA-256(
    storage_account +
    container +
    blob_name
)

Use a URL-safe representation.

Do NOT expose:
- Storage account keys
- SAS tokens
- credentials
- secrets

Do not use Python's built-in hash() because it is not stable across processes.

============================================================
4. FILE_ID TO BLOB RESOLUTION
============================================================

Implement a reliable mapping from:

file_id
    ↓
storage account
container
blob name

Prefer the simplest implementation that fits the existing application.

If the application already has a metadata/control store, reuse it.

If no metadata store exists, implement a secure signed/encoded blob reference or another deterministic mechanism that does NOT require introducing a new database solely for this feature.

Do NOT create a new database or Azure resource without first explaining why it is necessary.

The mapping must survive Function restarts.

Do NOT store file_id mappings only in Python memory.

============================================================
5. CREATE HTTP DOWNLOAD FUNCTION
============================================================

Add a new HTTP-trigger Azure Function.

Route:

/api/download

Request example:

GET /api/download?file_id=<file-id>

Use the existing Python v2 programming model if function_app.py already uses it.

Conceptual structure:

@app.route(
    route="download",
    methods=["GET"],
    auth_level=...
)
def download_file(req: func.HttpRequest) -> func.HttpResponse:
    ...

Follow the existing project's coding conventions.

============================================================
6. DOWNLOAD FUNCTION LOGIC
============================================================

The download Function must:

1. Read file_id from query parameters.

2. Validate:
   - file_id exists
   - file_id format is valid
   - file_id resolves to an approved blob
   - container/path is allowed
   - blob exists

3. Resolve file_id to:
   - storage account
   - container
   - blob name

4. Use Azure managed identity / DefaultAzureCredential.

5. Generate a fresh USER DELEGATION SAS for ONLY that blob.

6. SAS permissions should be READ ONLY.

7. SAS lifetime should be short.

Use:

DOWNLOAD_SAS_EXPIRATION_SECONDS=600

Default:
10 minutes.

Do NOT reuse the old long-lived Confluence SAS lifetime.

8. Construct the complete fresh Blob SAS URL.

9. Return:

HTTP 302

with:

Location: <fresh SAS URL>

Do NOT download the entire blob through the Function unless technically required.

The Function should redirect the browser directly to Blob Storage.

============================================================
7. USER DELEGATION SAS
============================================================

Reuse the existing User Delegation SAS implementation if one already exists.

Use:

DefaultAzureCredential

and BlobServiceClient.

Generate a User Delegation Key with a short validity window.

Then generate the blob SAS using:

generate_blob_sas(...)

Permissions:

BlobSasPermissions(read=True)

Do NOT grant:
- write
- delete
- create
- add

Use UTC-aware timestamps.

Allow a small negative start-time offset if required for clock skew, for example 5 minutes.

Example conceptual validity:

start  = now - 5 minutes
expiry = now + 10 minutes

Do not hard-code account keys.

============================================================
8. MANAGED IDENTITY / RBAC
============================================================

The Azure Function uses its system-assigned managed identity.

Reuse the existing Storage RBAC.

Verify that the identity has the permissions required to generate User Delegation SAS and read the target blob.

Existing architecture already includes roles such as:

Storage Blob Data Contributor
Storage Blob Delegator

Do NOT add Storage Blob Data Owner unless genuinely required.

Do NOT use Storage Account keys.

Do NOT use connection strings containing account keys.

============================================================
9. CONFLUENCE LINK CHANGE
============================================================

Change the existing Confluence page generation logic.

CURRENT:

Confluence page
    ↓
https://storage.../file.xlsx?<SAS>
    ↓
expires

NEW:

Confluence page
    ↓
https://<function-host>/api/download?file_id=<file-id>

The Confluence page must NEVER contain a Storage SAS token.

Generate the Function download URL dynamically using configuration.

Add a non-secret configuration variable:

For DEV this will ultimately point to the deployed Function App URL.

Do NOT hard-code the host throughout the Python source.

Build:

download_url = (
    f"{DOWNLOAD_FUNCTION_BASE_URL.rstrip('/')}"
    f"/api/download?file_id={urlencode(file_id)}"
)

Use proper URL encoding.

============================================================
10. IMPORTANT SECURITY REQUIREMENT
============================================================

Do NOT expose arbitrary blob access.

A malicious caller must NOT be able to supply:

?blob=../../...
?container=tfstate
?blob=<arbitrary-storage-path>

and receive a SAS.

file_id must resolve only to files that the SOX application has processed/approved.

Explicitly prevent access to infrastructure containers such as:

tfstate
function-packages
$logs

Do NOT allow the download endpoint to generate SAS URLs for arbitrary containers.

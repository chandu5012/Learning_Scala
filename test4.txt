Update the Terraform implementation for the SOX Azure Storage Queue Private Endpoint.

Repository:
vertexinc/vdf-soxcompliance-infra

Path:
azure-infra

IMPORTANT:
We now have a confirmed working internal Vertex reference from Sean Cooper.

The shared Private DNS zones are centrally managed.

Teams MUST NOT:
- create private_dns_zone_group
- join the shared Private DNS zone
- create/update VNet links for the shared DNS zone

Teams ARE allowed to:
1. Create the Private Endpoint.
2. Create an A record inside the centrally managed Private DNS zone.

The existing implementation currently uses private_dns_zone_group and fails with:

Microsoft.Network/privateDnsZones/join/action

LinkedAuthorizationFailed.

Replace that design with the working internal pattern described below.

============================================================
1. UPDATE providers.tf
============================================================

Keep the existing default provider:

provider "azurerm" {
  features {}

  subscription_id     = var.subscription_id
  tenant_id           = var.tenant_id
  storage_use_azuread = true
}

Add a second provider for PDD Shared Resources:

provider "azurerm" {
  alias = "shared_resources"

  features {}

  subscription_id = var.shared_resources_subscription_id
  tenant_id       = var.tenant_id
}

Do not replace the default provider.

The default provider continues managing the SOX resources in:

PDD CrossNet Development
Subscription:
be54cf53-5579-48b9-83eb-60ced48deccb

The aliased provider is only for DNS records in:

PDD Shared Resources
Subscription:
19feb3b2-c4c1-40fe-a23f-07491fdf66dc

============================================================
4. UPDATE main.tf - PRIVATE ENDPOINT
============================================================

Find the existing:

resource "azurerm_private_endpoint" "storage_queue"

Replace it with:

resource "azurerm_private_endpoint" "storage_queue" {
  count = local.file_processing_enabled ? 1 : 0

  name                = "${var.queue_name}-pe"
  location            = data.azurerm_resource_group.shared.location
  resource_group_name = data.azurerm_resource_group.shared.name
  subnet_id           = var.storage_privatelink_subnet_id

  private_service_connection {
    name                           = "${var.queue_name}-psc"
    private_connection_resource_id = data.azurerm_storage_account.shared.id
    subresource_names              = ["queue"]
    is_manual_connection           = false
  }

  tags = var.tags
}

CRITICAL:

There must be NO:

private_dns_zone_group {
  ...
}

inside this resource.

Do NOT create any private DNS zone group.
Do NOT attempt privateDnsZones/join/action.

============================================================
5. ADD SEPARATE QUEUE PRIVATE DNS A RECORD
============================================================

Immediately after the azurerm_private_endpoint.storage_queue
resource, add:

resource "azurerm_private_dns_a_record" "storage_queue" {
  count = local.file_processing_enabled ? 1 : 0

  provider = azurerm.shared_resources

  name                = data.azurerm_storage_account.shared.name
  zone_name           = "privatelink.queue.core.windows.net"
  resource_group_name = "pdd-sr-global-ce-private-links-east-us-2"
  ttl                 = 300

  records = [
    azurerm_private_endpoint.storage_queue[0].private_service_connection[0].private_ip_address
  ]
}

This follows the confirmed working internal Vertex pattern.

For the storage account:

vtxcusvdpdataplatfe1a54

the resulting DNS A record should conceptually be:

vtxcusvdpdataplatfe1a54.privatelink.queue.core.windows.net

pointing to the private IP allocated to:

azurerm_private_endpoint.storage_queue[0]

Do NOT hardcode the private IP.

Always obtain it using:

azurerm_private_endpoint.storage_queue[0].private_service_connection[0].private_ip_address

This ensures that if the Private Endpoint is recreated and receives a
different private IP, Terraform updates the DNS A record automatically.

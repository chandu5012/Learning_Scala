============================================================
REPORT DETAILS PAGE AND OUTPUT TABLE
============================================================

After creating/finding the hierarchy:

ROOT_PARENT_ID/<YEAR>/<SOURCE>/<REPORT_TYPE>

do NOT create a separate Confluence page for every file.

Instead, under each REPORT_TYPE folder, maintain ONE Confluence page named:

Report Details

Example S3 object:

sox-reports/2026/Snowflake/ITGC02/report1.csv

Required Confluence structure:

ROOT_PARENT_ID
└── 📁 2026
     └── 📁 Snowflake
          └── 📁 ITGC02
               └── 📄 Report Details
                    └── Output table containing report/file details

For another file:

sox-reports/2026/Snowflake/ITGC02/report2.csv

DO NOT create another "Report Details" page.

Instead:

1. Find the existing "Report Details" page directly under the ITGC02 folder.
2. Read the existing page content.
3. Append a new row to the existing output table.
4. Update the same Confluence page.

Expected result:

📁 ITGC02
   └── 📄 Report Details

       | File Name   | Source    | Report Type | Year | File Link |
       |-------------|-----------|-------------|------|-----------|
       | report1.csv | Snowflake | ITGC02      | 2026 | Download  |
       | report2.csv | Snowflake | ITGC02      | 2026 | Download  |
       | report3.csv | Snowflake | ITGC02      | 2026 | Download  |

The File Link column must contain the existing generated S3/download link
using the application's current link-generation logic.

If the existing application has additional output fields/columns, preserve
them and add the new row using the same table structure.

============================================================
REPORT DETAILS PAGE LOGIC
============================================================

After obtaining:

report_type_folder_id

execute:

get_or_create_report_details_page(report_type_folder_id)

IMPORTANT:

Search for "Report Details" ONLY under report_type_folder_id.

Do NOT search globally for a page named "Report Details".

There can be many pages with the same name:

2026/Snowflake/ITGC02/Report Details
2026/Snowflake/ITGC03/Report Details
2026/AWS/ITGC02/Report Details
2027/Snowflake/ITGC02/Report Details

These are separate pages because they belong to different parent folders.

The logical identity is:

report_type_folder_id + "Report Details"

============================================================
FIRST FILE
============================================================

Example:

sox-reports/2026/Snowflake/ITGC02/report1.csv

If the hierarchy does not exist:

1. Find/create 2026 under ROOT_PARENT_ID.
2. Find/create Snowflake under the 2026 folder.
3. Find/create ITGC02 under the Snowflake folder.
4. Check for a page named "Report Details" directly under ITGC02.
5. If "Report Details" does NOT exist:
   - Create a normal Confluence PAGE named "Report Details".
   - Parent must be ITGC02 folder ID.
   - Create the output table.
   - Add report1.csv as the first data row.
   - Include the generated file/download link.
6. Capture and log the Report Details page ID.

Result:

ROOT_PARENT_ID
└── 📁 2026
     └── 📁 Snowflake
          └── 📁 ITGC02
               └── 📄 Report Details
                    |
                    | File Name   | Source    | Report Type | Year | File Link |
                    | report1.csv | Snowflake | ITGC02      | 2026 | Download  |

============================================================
SECOND AND SUBSEQUENT FILES
============================================================

Suppose later this file arrives:

sox-reports/2026/Snowflake/ITGC02/report2.csv

The code must:

1. Find existing 2026.
2. Find existing Snowflake.
3. Find existing ITGC02.
4. Find existing "Report Details" page under ITGC02.
5. DO NOT create another Report Details page.
6. Retrieve the existing Report Details page content.
7. Retrieve the current Confluence page version.
8. Append a new row for report2.csv to the EXISTING table.
9. Preserve all existing rows.
10. Update the same Report Details page using the next required Confluence
    page version.

Expected result:

| File Name   | Source    | Report Type | Year | File Link |
|-------------|-----------|-------------|------|-----------|
| report1.csv | Snowflake | ITGC02      | 2026 | Download  |
| report2.csv | Snowflake | ITGC02      | 2026 | Download  |

Never overwrite/remove report1.csv when adding report2.csv.

============================================================
DUPLICATE FILE / SQS RETRY HANDLING
============================================================

SQS/Lambda can process the same event more than once.

Therefore the Report Details page update must also be idempotent.

Example:

Lambda receives:

sox-reports/2026/Snowflake/ITGC02/report1.csv

twice.

Do NOT produce:

| report1.csv | ... |
| report1.csv | ... |

Before appending a row, determine whether the same report/file has already
been added.

Prefer using a stable identifier such as:

S3 bucket + complete S3 object key

Example:

bucket:
vdp-sox-reports

key:
sox-reports/2026/Snowflake/ITGC02/report1.csv

Logical unique report identifier:

vdp-sox-reports +
sox-reports/2026/Snowflake/ITGC02/report1.csv

If this object is already represented on the Report Details page, do not
append another row.

Log:

REPORT ALREADY EXISTS - skipping duplicate row

If the same file name can be uploaded as a new version and the business
requirement is to show every version, preserve version-specific metadata
such as S3 version ID where available. Otherwise treat the same S3 object
key as the same report.

============================================================
TABLE HANDLING
============================================================

Do not recreate the complete page blindly for every file.

When Report Details already exists:

1. GET the current page.
2. Obtain the existing page body in the representation required by the
   existing Confluence API.
3. Obtain the current page version.
4. Locate the existing report table.
5. Preserve the header.
6. Preserve all existing rows.
7. Append the new row.
8. Preserve other existing page content.
9. Increment/update the Confluence page version correctly.
10. PUT/update the existing page.

Do not destroy other content that may already exist on Report Details.

Use valid Confluence storage/ADF format according to the API already being
used by this project.

Do not assume HTML is accepted until the existing Confluence API
implementation has been inspected.

============================================================
CONCURRENT PAGE UPDATES
============================================================

This is important because multiple S3/SQS events can execute simultaneously.

Example:

report1.csv
report2.csv

Two Lambda invocations may attempt to update the same:

2026/Snowflake/ITGC02/Report Details

at the same time.

Do not allow one update to silently overwrite another.

Use Confluence page versioning/conflict handling.

If the update fails because the page version changed:

1. Fetch the latest Report Details page again.
2. Re-check whether the current file row already exists.
3. If it does not exist, append it to the latest table.
4. Retry the page update using the latest version.
5. Use a bounded retry count.
6. Do not retry indefinitely.

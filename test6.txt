The issue is storage RBAC for the Function App system-assigned managed identity.

============================================================
1. UPDATE THE EXISTING BLOB ROLE ASSIGNMENT
============================================================

Find the existing role assignment similar to:

resource "azurerm_role_assignment" "function_storage_blob" {
  count                = local.file_processing_enabled ? 1 : 0
  scope                = data.azurerm_storage_account.shared.id
  role_definition_name = "Storage Blob Data Reader"
  principal_id         = azurerm_linux_function_app.function[0].identity[0].principal_id
}

Change ONLY:

role_definition_name = "Storage Blob Data Reader"

to:

role_definition_name = "Storage Blob Data Contributor"

The final block should be:

resource "azurerm_role_assignment" "function_storage_blob" {
  count                = local.file_processing_enabled ? 1 : 0
  scope                = data.azurerm_storage_account.shared.id
  role_definition_name = "Storage Blob Data Contributor"
  principal_id         = azurerm_linux_function_app.function[0].identity[0].principal_id
}

Reason:
AzureWebJobsStorage requires write access to blobs for Function host/runtime state and leases.
Storage Blob Data Reader is insufficient.

============================================================
2. KEEP THE EXISTING QUEUE ROLE ASSIGNMENT
============================================================

Do NOT remove or downgrade the existing Queue role.

It should remain similar to:

resource "azurerm_role_assignment" "function_storage_queue" {
  count                = local.file_processing_enabled ? 1 : 0
  scope                = data.azurerm_storage_account.shared.id
  role_definition_name = "Storage Queue Data Contributor"
  principal_id         = azurerm_linux_function_app.function[0].identity[0].principal_id
}

Keep this unchanged.

============================================================
3. ADD TABLE DATA ROLE IF NOT ALREADY PRESENT
============================================================

Check whether a role assignment already exists for:

Storage Table Data Contributor

If it does not exist, add:

resource "azurerm_role_assignment" "function_storage_table" {
  count                = local.file_processing_enabled ? 1 : 0
  scope                = data.azurerm_storage_account.shared.id
  role_definition_name = "Storage Table Data Contributor"
  principal_id         = azurerm_linux_function_app.function[0].identity[0].principal_id
}

Reason:
Azure Functions host storage / Durable Functions may require Table access.
Adding this prevents AzureWebJobsStorage failures if table storage is used by the runtime.

Do not create duplicate role assignments if this role already exists.

============================================================
4. KEEP STORAGE BLOB DELEGATOR IF ALREADY PRESENT
============================================================

If this role exists:

role_definition_name = "Storage Blob Delegator"

leave it unchanged.

It is used for user-delegation SAS and is separate from Function host storage access.

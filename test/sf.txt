# MASTER DEVELOPMENT PROMPT
## VDP Snowflake 360° — Enterprise Monitoring, Billing, FinOps & Optimization Dashboard

### 1. Objective

Develop a complete, production-quality, modular Snowflake 360° dashboard using **Python, Gradio, Plotly, Polars and Snowflake Connector**.

The application must connect to real Snowflake accounts and provide comprehensive analysis of:

- Billing, credits and cost consumption
- Warehouses and compute utilization
- Tasks and task execution history
- Dynamic tables and refresh performance
- Databases, schemas, tables and storage
- Streams, Snowpipe and ingestion
- Queries and query performance
- Users, roles and security
- Resource monitors and governance
- Cost allocation by account, application, database, user and workload
- FinOps optimization and recommendations
- Snowflake warehouse consolidation
- Failure analysis and operational health
- Historical trends and forecasting
- Complete Excel, CSV and PDF reports

**Important:** This is NOT just a warehouse consolidation application. It must be a comprehensive Snowflake Administration, Monitoring, Billing and FinOps platform.

All metrics must come from real Snowflake metadata, account usage views and billing sources.

Do not use dummy data, mock results or hardcoded billing values in production mode.

The initial implementation must be READ-ONLY.

- INFORMATION_SCHEMA

- Query history

Validate the exact Snowflake view names, columns, required privileges, retention and latency against official documentation before writing SQL.

Do not assume every ACCOUNT_USAGE view has identical retention or latency.

- Configurable lookback periods
- Incremental collection where practical
- Caching
- Query timeouts
- Retry handling
- Connection pooling where safe
- Collection status
- Missing-permission detection
- Partial-result warnings

Avoid full account-history scans on every dashboard refresh.
